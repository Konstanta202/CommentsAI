# Вариант 4: Аналитика студенческой жизни и академического стресса

## Предметная область

Анализ активности и эмоционального фона студенческих сообществ ВКонтакте («Подслушано [ВУЗ]», паблики факультетов) в привязке к учебному календарю — сессии, дедлайны, каникулы.

Категория по классификации методички: **Social Mining** + **Text Mining**. Прямое попадание в явно поощряемый методичкой домен **«Образование»** (стр. 10).

## Практическая ценность

- Понимание пиков академического стресса помогает вузам планировать периоды повышенной нагрузки на психологическую поддержку студентов.
- Сравнение между вузами/факультетами показывает различия в студенческой культуре и уровне вовлечённости.
- Реальный кейс для деканатов/студсоветов — «когда и по каким темам студентам нужна поддержка».

## Что и как собираем

**Источники**: студенческие паблики 3-5 вузов (официальные «Подслушано [ВУЗ]» или паблики факультетов) — для сравнения между учебными заведениями.

**Поля**: те же, что и в остальных вариантах (посты + комментарии + треды + счётчики), собираются одним и тем же парсером без изменений кода.

**Объём**: студенческие паблики обычно менее многолюдны, чем городские «Подслушано» — может понадобиться больше групп или более длинный период сбора, чтобы дотянуть до 2 ГБ. Это стоит проверить контрольным прогоном в первую очередь.

**Период**: минимум один полный учебный год (сентябрь-июнь), чтобы захватить обе сессии (зимнюю и летнюю) — это ключевое для задач, завязанных на учебный календарь.

## Архитектура

```
VK Parser (Java) → Kafka → Ingestion/Cleaning (Python)
                                    ↓
                              MongoDB (сырое хранилище, обязательная NoSQL)
                                    ↓
                    Обработка (pandas/sklearn + PySpark + LLM API)
                                    ↓
                         ClickHouse (аналитическая витрина)
                                    ↓
                    Gateway (FastAPI, JWT) → React-дашборд + Grafana
```

Архитектура идентична остальным вариантам — меняется только список групп и разметка учебного календаря (даты сессий) как внешнего справочника для сопоставления с активностью.

## Распределение ролей и задач (20 задач)

### Джавист — временная и инфраструктурная динамика
1. Динамика активности, привязанная к учебному календарю (сессии/дедлайны/каникулы) *(статистическая)*
2. Время реакции сообщества на посты про стресс/дедлайны *(статистическая)*
3. Кластеризация вузов/факультетов по профилю активности в течение года *(исследовательская)*
4. Прогноз декабрьского/июньского пика активности по данным сентября-октября *(исследовательская)*
5. Оценка полноты/потерь данных из-за rate-limit при сборе за учебный год *(статистическая)*

### Fullstack #1 — AI/RAG/LLM-аналитика содержания
1. LLM-классификация постов по теме (учёба/быт/юмор/жалобы/стресс) без дообучения *(исследовательская)*
2. Тональность и эмоциональный фон в период сессии vs вне сессии *(статистическая)*
3. Тематическое моделирование — какие темы доминируют в разные периоды учебного года *(исследовательская)*
4. RAG-бот: «какие проблемы чаще всего упоминают студенты факультета X перед сессией» *(исследовательская)*
5. Сравнение LLM-классификации со словарём «стресс-маркеров» (lexicon-baseline) *(исследовательская)*

### Fullstack #2 — сетевой анализ и тяжёлая обработка
1. Граф обсуждений — кто активнее всего комментирует (лидеры мнений/популярные авторы) *(исследовательская)*
2. Детект накрутки/рекламных вбросов под видом студентов (курсы, репетиторы) *(исследовательская)*
3. Кросс-групповой анализ — общие авторы между разными вузами (переводники, паблики-дубли) *(исследовательская)*
4. PySpark: частотный анализ лексики по учебным периодам на всём корпусе *(исследовательская, закрывает критерий Hadoop-экосистемы)*
5. Доля постов с высокой вовлечённостью vs незамеченных *(статистическая)*

### Аналитик — описательная статистика
1. Распределение длины постов и корреляция с лайками (Пирсон/Спирмен) *(статистическая)*
2. Динамика объёма постов по неделям учебного года — тренд *(статистическая)*
3. Сравнение активности между вузами/факультетами, топ-N самых обсуждаемых тем *(статистическая)*
4. Сводная статистика по темам постов (на основе вывода Fullstack #1) *(статистическая)*
5. Проверка гипотезы: значимо ли выше негатив/активность в сессионный период (t-test) *(исследовательская)*

## Риски и особенности

- Меньшая аудитория студенческих пабликов относительно городских — риск не набрать 2 ГБ без расширения списка групп. Стоит закладывать больше источников с запасом.
- Учебные календари у разных вузов немного отличаются по датам — нужен небольшой справочник дат сессий по каждому вузу для точной привязки.

## Соответствие критериям методички

| Критерий | Как выполнено |
|---|---|
| Объём данных ≥2ГБ | Требует больше групп/более длинного периода, чем городской вариант — риск, но выполнимо |
| 5-20 задач, статистика+исследование | 20 задач, оба типа представлены у каждого участника |
| NoSQL БД | MongoDB как сырое документ-хранилище |
| Экосистема Hadoop/Spark | PySpark-задача у Fullstack #2 |
| Продвинутые методы | LLM-классификация, эмбеддинги, RAG, привязка к календарным событиям |
