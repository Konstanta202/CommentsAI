# Вариант 6: Аналитика IT-трендов в русскоязычном VK-комьюнити

## Предметная область

Анализ того, какие технологии, языки программирования и фреймворки обсуждаются в русскоязычных IT-пабликах ВКонтакте, и как это меняется во времени — прямой аналог задачи 2 из референсного примера другой команды («Анализ данных с сайта StackOverflow»), но на другом источнике данных.

Категория по классификации методички: **Social Mining** + **Text Mining**. Домен **«ИТ»**, явно поощряемый методичкой (стр. 10).

## Практическая ценность

- Понимание, какие технологии набирают/теряют популярность в русскоязычном сегменте — полезно для образовательных программ и карьерных решений студентов.
- Прямая параллель с примером про HeadHunter из самой методички (стр. 12-13) и с темой соседней команды (StackOverflow) — на защите легко объяснить: «мы делаем то же самое исследование, но на независимом источнике, для кросс-валидации выводов».
- Демонстрирует применимость подхода не только к «мягким» темам (новости/жалобы), но и к точным техническим данным.

## Что и как собираем

**Источники**: 4-6 крупных IT-пабликов — паблики конкретных языков/фреймворков, паблики вакансий в IT, паблики конференций/митапов, паблики типа «Типичный программист».

**Поля**: те же, что и в остальных вариантах — парсер не меняется.

**Объём**: IT-паблики в VK не всегда так активны по комментариям, как развлекательные/городские паблики — это главный риск варианта. Компенсируется увеличением количества источников и глубины истории.

**Период**: 2-3 года истории (аналогично временному охвату 2002-2016 в примере методички по HeadHunter) — чтобы поймать реальную динамику смены технологий, а не шум одного сезона.

## Архитектура

```
VK Parser (Java) → Kafka → Ingestion/Cleaning (Python)
                                    ↓
                              MongoDB (сырое хранилище, обязательная NoSQL)
                                    ↓
                    Обработка (pandas/sklearn + PySpark + LLM API)
                                    ↓
                         ClickHouse (аналитическая витрина)
                                    ↓
                    Gateway (FastAPI, JWT) → React-дашборд + Grafana
```

Архитектура идентична остальным вариантам — меняется только список групп и справочник технологий/языков для NER-извлечения.

## Распределение ролей и задач (20 задач)

### Джавист — временная и инфраструктурная динамика
1. Динамика активности IT-пабликов по месяцам/годам *(статистическая)*
2. Время реакции комьюнити на посты о релизах новых технологий *(статистическая)*
3. Кластеризация пабликов по профилю активности во времени *(исследовательская)*
4. Прогноз виральности поста о новой технологии по ранним признакам *(исследовательская)*
5. Оценка полноты/потерь данных из-за rate-limit при сборе за несколько лет истории *(статистическая)*

### Fullstack #1 — AI/RAG/LLM-аналитика содержания
1. Извлечение упоминаний технологий/языков программирования через LLM (NER-подобная задача) без дообучения *(исследовательская)*
2. Тональность обсуждений конкретных технологий (позитив/хейт к языку/фреймворку) *(статистическая)*
3. Тематическое моделирование — динамика «горячих» тем IT-сообщества *(исследовательская)*
4. RAG-бот: «что комьюнити думает о технологии X за последний год» *(исследовательская)*
5. Сравнение LLM-экстракции технологий с regex/эталонным списком-baseline *(исследовательская)*

### Fullstack #2 — сетевой анализ и тяжёлая обработка
1. Граф обсуждений — кто формирует мнение (топ-комментаторы/евангелисты технологий) *(исследовательская)*
2. Детект рекламных ботов (продвижение курсов/технологий под видом органических комментариев) *(исследовательская)*
3. Кросс-групповой анализ авторов между разными IT-пабликами *(исследовательская)*
4. PySpark: частотный анализ упоминаний технологий на всём корпусе — аналог задачи 3 из примера StackOverflow («% решённых вопросов по технологии»), адаптированной под «% позитивных упоминаний по технологии» *(исследовательская, закрывает критерий Hadoop-экосистемы)*
5. Сравнение динамики популярности технологий в VK-комьюнити с открытыми данными/оценками по StackOverflow, если такие есть в доступе *(исследовательская)*

### Аналитик — описательная статистика
1. Распределение длины комментариев и корреляция с лайками (Пирсон/Спирмен) *(статистическая)*
2. Динамика объёма постов по кварталам/годам — тренд, аналогично методическому примеру *(статистическая)*
3. Сравнение активности по пабликам и топ-N обсуждаемых технологий *(статистическая)*
4. Сводная статистика по тональности технологий (на основе вывода Fullstack #1) *(статистическая)*
5. Проверка гипотезы: значимо ли упала активность обсуждения языка X после выхода технологии Y — прямая параллель с гипотезой «снижение популярности сайта из-за нейросетей» из референсного примера *(исследовательская)*

## Риски и особенности

- Главный риск — объём данных: IT-паблики менее «разговорчивы», чем развлекательные/городские. Нужен контрольный прогон на старте, чтобы понять, хватит ли 4-6 групп за 2-3 года, или расширять список.
- Список технологий/языков для NER-извлечения нужно поддерживать вручную (регулярно обновляемый словарь) — небольшая дополнительная работа для Fullstack #1.

## Соответствие критериям методички

| Критерий | Как выполнено |
|---|---|
| Объём данных ≥2ГБ | Требует больше групп/длинного периода (2-3 года) — главный риск варианта |
| 5-20 задач, статистика+исследование | 20 задач, оба типа представлены у каждого участника |
| NoSQL БД | MongoDB как сырое документ-хранилище |
| Экосистема Hadoop/Spark | PySpark-задача у Fullstack #2 |
| Продвинутые методы | LLM/NER-извлечение, эмбеддинги, RAG, кросс-источниковое сравнение |
